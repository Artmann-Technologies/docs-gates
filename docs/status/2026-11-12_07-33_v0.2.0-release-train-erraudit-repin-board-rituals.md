## e) WHAT WE SHOULD IMPROVE

1. **Claim-before-drive for releases.** A "release in flight — claimed
   by <session>" board row (or tag-namespace convention) would have
   prevented today's double-drive. Process, one AGENTS paragraph.
2. **Check the tool's universe BEFORE invoking the tool.** 15 minutes
   burned because I never asked "is AGENTS.md even in the pre-flight
   corpus". Read the loader's scope first, then run the gate.
3. **Candidates go through `write`, never printf pipes.** Byte-verifiable
   files would have exposed the `\`` artifacts immediately.
4. **Under the auto-commit daemon, `git restore <path>` restores from
   the INDEX** — staged edits make it a no-op. Document
   `--source=HEAD` as the repo reflex.
5. **`git ls-remote --tags` immediately before cutting any release
   tag** in a repo that runs concurrent sessions.
6. **Freshness UX (this repo): the on-disk refusal should print the
   matching DISK line** next to the colliding candidate — today I had
   to read the gate's source to understand a refusal.
7. **Freshness UX (this repo): pre-flight should refuse candidates
   naming a file outside the living-docs corpus** with "AGENTS.md is
   not in the corpus" instead of the misleading --replace
   target-not-found path.
8. **safe-strike UX: echo the parsed positionals in refusals** so a
   missing `<file>` names itself instead of masquerading as a missing
   verdict.
9. **Lockfile bump + tripwire re-pin should be ONE train** — the
   tripwire did its job catching the interim red, but the bumping
   session leaving `expected_rev` stale is the preventable half.
10. **Version-skev between CI's pinned golangci action and the local
    fleet binary is real** (CI flagged a subset of local findings) —
    the `golangci-drift` check pins versions, not linter-set parity;
    worth a conscious decision next time the pin bumps.
